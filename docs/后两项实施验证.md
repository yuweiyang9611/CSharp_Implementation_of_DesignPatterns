# 多进程可靠性与浏览器 C# 练习：实施验证

验证日期：2026-09-12。环境：Windows、.NET SDK 10.0.401、Node.js 24、无头 Microsoft Edge。WebAssembly 使用安装了 wasm-tools、wasm-experimental 的独立 SDK；系统级工作负载安装遇到 MSI 取消后，改用独立 SDK 完成验证。站点 CI 固定同版 SDK。

## 交付内容

- ReliableCheckout：库存预留、确认取消、独立支付账本、版本迁移与历史失败订单补偿；租约领取／续期／接管、最大投递次数、死信与本地重放审计。
- 学习站：原有 6 道辨析题 ID／版本保留，扩展到 24 道，其中 4 道选择简单实现；关联模式覆盖 GoF 23 种。8 道共享源码的 C# 练习支持浏览器编译与验收。
- 编码记录单独统计，草稿按题目 ID／版本存储；原有进度、复习及 JSON 备份继续兼容，保存失败提示和紧急备份保留。
- ReliableCheckout 追加 4 个里程碑；发布目录生成任务、题目及页面数量。本次生成 120 个学习任务、38 个页面，编码题单独统计为 8 道。

## 故障与兼容性证据

[ReliabilityTests](../labs/ReliableCheckout/ReliableCheckout.Tests/ReliabilityTests.cs) 验证重复失败仅归还一次库存、未知结果保留预留、取消早于创建、支付与取消竞争、租约续期及接管、旧租约操作拒绝、死信轮次与审计、末次领取崩溃进入死信，以及旧数据库连续升级检查。已有回调收据在旧平台账本不存在时仍可重放。

[ProcessRecoveryTests](../labs/ReliableCheckout/ReliableCheckout.Tests/ProcessRecoveryTests.cs) 真正终止独立子进程，分别覆盖“平台接受、本地收据未提交”和“消费提交、Outbox 未确认”。恢复后验证订单、库存、收据及支付创建数量。双进程场景等待两个宿主均开始监听，再通过 HTTP 创建订单。

[ExerciseTests](../tests/GuideExporter.Tests/ExerciseTests.cs) 与 [浏览器回归](../tests/playground-regression.mjs) 使用同一个 [题目源](../site/data/coding-exercises.json)：8 份初始实现均产生预定验收失败，8 份参考答案全部通过。浏览器还验证 C# 14 扩展块实际编译执行、语法错误、运行异常、输出截断、执行超时、停止后重跑、源码限制、备份恢复及旧复习记录。加载和编译截止时间用受控停滞 Worker 与页面时钟验证。

站点回归在 `/course/` 子路径运行，验证 GitHub Pages 仓库路径下的资源定位。桌面 1440px、移动端 390px 无文档横向溢出，axe 无 serious／critical 问题。截图位于 `output/site-regression/playground-1440.png` 与 `playground-390.png`。

## 复核命令

```powershell
pwsh -File scripts/verify.ps1 -Mode Quick
dotnet test labs/ReliableCheckout/ReliableCheckout.slnx -c Release
dotnet workload install wasm-tools wasm-experimental
pwsh -File scripts/verify.ps1 -Mode Full -SkipPdf
node tests/site-server.mjs
# 浏览器打开 http://localhost:4173/playground.html
```

系统 SDK 的 workload list 为空时，实际执行 Quick -NoRestore 也已通过。Quick 不包含浏览器项目，无需 WebAssembly 工作负载。本地 outbox list 返回有效 JSON，不存在的事件重放返回约定的退出码 2；死信成功重放与审计由可靠性测试验证。完整运行和故障处理说明见 [README](../README.md#浏览器-c-练习与构建) 与 [ReliableCheckout 教程](../labs/ReliableCheckout/README.md)。
